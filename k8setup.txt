Kubernetes Complete 50-Minute Demo Explanation

INTRODUCTION TO KUBERNETES

What is Kubernetes?

Kubernetes is a container orchestration platform used to automate:
- container deployment
- scaling
- networking
- self healing
- load balancing
- application management

It is widely used in DevOps and cloud environments.

WHY KUBERNETES IS NEEDED

Before Kubernetes:
- Applications were deployed directly on servers.
- Managing many applications was difficult.
- Scaling applications manually was hard.
- If a server crashed, applications went down.
- Managing containers at large scale became complex.

Kubernetes solves these problems.

REAL-TIME EXAMPLE

Imagine Netflix.

Millions of users watch videos continuously.

Netflix uses thousands of containers.

Kubernetes helps:
- automatically scale applications
- restart failed containers
- distribute traffic
- maintain high availability
- deploy updates without downtime

KUBERNETES ARCHITECTURE

Basic Architecture Flow

kubectl → API Server → Kubernetes Cluster

IMPORTANT KUBERNETES COMPONENTS

1. Cluster
A Kubernetes cluster is a collection of nodes.

2. Node
A node is a machine where containers run.

3. Pod
A pod is the smallest deployable unit in Kubernetes.

4. Deployment
Deployment manages pods.

5. ReplicaSet
ReplicaSet ensures required number of pods are always running.

6. Service
A Service exposes applications.

CHECKING RESOURCES

Command:
kubectl get all

DEPLOYMENT YAML FILE

File:
deployments/nginx-deployment.yaml

YAML CODE:

apiVersion: apps/v1
kind: Deployment

metadata:
  name: nginx-deployment

spec:
  replicas: 4

  selector:
    matchLabels:
      app: nginx

  template:
    metadata:
      labels:
        app: nginx

    spec:
      containers:
      - name: nginx
        image: nginx
        ports:
        - containerPort: 80

EXPLANATION OF YAML

apiVersion:
Defines Kubernetes API version.

kind:
Defines resource type.

metadata:
Stores object information.

spec:
Defines desired state.

replicas:
Defines number of pod copies.

selector:
Used to identify matching pods.

template:
Defines pod template.

containers:
Defines container configuration.

image:
Defines Docker image.

APPLYING YAML FILE

Command:
kubectl apply -f deployments/nginx-deployment.yaml

Output:
deployment.apps/nginx-deployment created

CHECKING PODS

Command:
kubectl get pods

Output:
4 running nginx pods.

SELF HEALING CONCEPT

If one pod crashes:
ReplicaSet recreates it automatically.

This feature is called:
Self Healing

LIVE MONITORING

Command:
kubectl get pods -w

Purpose:
Watch pods continuously in real time.

CREATING SERVICE YAML

File:
services/nginx-service.yaml

YAML CODE:

apiVersion: v1
kind: Service

metadata:
  name: nginx-service

spec:
  selector:
    app: nginx

  ports:
    - protocol: TCP
      port: 80
      targetPort: 80

  type: NodePort

EXPLANATION OF SERVICE YAML

kind: Service
Defines Kubernetes Service resource.

selector:
Selects matching pods.

ports:
Defines networking.

type: NodePort
Exposes application outside cluster.

APPLYING SERVICE YAML

Command:
kubectl apply -f services/nginx-service.yaml

Output:
service/nginx-service created

CHECKING SERVICES

Command:
kubectl get services

Output:
NAME            TYPE        CLUSTER-IP      EXTERNAL-IP   PORT(S)
nginx-service   NodePort    10.97.140.175   <none>        80:32052/TCP

EXPLANATION

80:32052/TCP

Meaning:
- Internal application port = 80
- External Kubernetes NodePort = 32052
